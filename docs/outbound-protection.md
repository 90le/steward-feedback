# Bot 消息出口敏感信息保护

Steward 将敏感信息保护落实在可信程序的对外发送路径中。模型可以正常调查和组织回答；凭证匹配、目标约束及是否允许外发由程序检查，不能靠聊天中的授权声明改变。

## 解决什么问题

保护 Bot 对外消息中的已知运行凭证、受保护文件路径和文件内容，降低模型误答、引用预览、附件或重试造成的外泄风险。本方案聚焦 Bot 的对外输出，不承担宿主服务器已经被攻破后的防护。

## 具体方案

| 环节 | 程序措施 |
| --- | --- |
| 获取保护依据 | 可信代码使用当前已解析的运行凭证和受保护文件作为匹配依据，不把匹配清单交给模型。 |
| 入队之前 | 检查候选正文及嵌套内容，原消息引用在截断前检查；敏感原文不进入新建的对外发送队列。 |
| 实际发出之前 | 直接回复、异步通知和旧队列恢复再次检查；Octo 通用发送、编辑及受支持的附件路径也有检查。 |
| 附件与公开文件 | 检查文件来源、文件名及支持范围内的文本内容；文本附件完整检查后才上传，超限或无法检查时拒绝未检查内容。 |
| 命中之后 | 能保留有效解释时重建安全答复；否则使用固定提示或不发送。重新计算原生提及偏移，并检查重建后的正文与引用。 |
| 重试与回执 | 只重试已检查的安全内容；旧发送结果不确定时先对账，不重发敏感原文。替代提示送达不算原业务完成。 |
| 审计 | 记录规则代码、必要交付标识及状态，不在拦截审计中复制命中秘密或敏感原答。 |

同一保护边界也用于 GitHub 公开写入：事项、需求、评审及公开文件在登记意图和实际发出前分别检查；编码后的文件先检查其解码明文。检测到敏感内容，不自动发布替代 PRD，也不将其计为业务成功。

## 为什么不只写一句“不要泄露”

提示词可以说明要求，但无法单独覆盖引用、附件、异步通知和重试。出口程序在真正产生外部效果之前检查最终内容；检查失败或依据不可用时拒绝未检查的外发。被保护拦截的结果标记为 `protected`，与正常完成分开，不触发原业务成功回调。

## 已验证的范围

- 代码与假服务检查覆盖匹配、正常业务放行、引用、提及偏移、轮换、重复发送、异常和对账等路径。
- 早期专项中，小丘的普通回复、安全替代回复、固定提示、异步通知四类均经过独立发送与再次同步核对；重复异步执行没有再次发送。这组探针没有模型调用，不等同于完整 Agent 回合或全部角色现场覆盖。
- 后续实际对话、防护修复与部署状态另见[安全验证记录](security.md)及[交付记录](delivery.md)。各批次与版本分别记载，不把合成检查、历史探针和真实模型运行混为一个通过结论。

## 适用边界

检查覆盖已知敏感值、受保护文件及限定的转义、编码和长片段形态，不保证识别未知秘密、任意分片、多重编码或所有图片音视频内容。资源隔离仍是基础，出口检查是额外保护。已有私有入站与会话历史也不等于新增的拦截审计，不宣称过滤器能够撤回旧版本已经发出的内容。
