# 项目介绍：让产品反馈持续推进

## 三分钟介绍

Steward 是服务于 Octo 的产品管家与交付团队。用户在 Octo 提问或反馈，小丘先读源码、澄清问题、查询已有事项；该登记的反馈进入公开需求池。功能需求由小助写 PRD，小衡独立评审，按意见修订。通过评审的 PRD 自动交给小码开发演示、小检实际测试，再由小衡复核。用户在原对话里收到有产物链接的结果。

我们最重视的是：**让 Agent 有足够信息调查问题，同时让关键动作有可以检查的前置条件。** Agent 可以多轮搜索、续读、比较源码和 Issue 评论，自主调整判断；Worker 管理身份、任务、版本、权限与外部回执。模型说“查过了”“通过了”，不能替代查询记录、独立评审或测试结果。

这一点能从 #8 看见：PRD 曾加入原始诉求没有要求的次数限制，外部意见被扫描发现后，v3 撤回多加的条件并复审。后续五角色流程生成了可运行演示，独立 HTTP 测试通过，再发布代码、报告和预览。这个案例同时说明独立评审有价值，也说明评审模型仍可能遗漏，需要保留外部纠正入口。

系统每 120 秒自动检查源码与需求池。没有变化时不调用模型、不发过程消息；发现新 Feature、补充意见或状态变化才推进对应业务。遇到知识缺口或持续阻塞，会说明不知道什么、请配置负责人核实什么，并保存通知与回执。任务没有结果时，不用“正在检查”“一切正常”刷屏。

当前已经完成五角色的演示交付样例；公开页面使用模拟数据，可下载运行演示后端。修改 Octo 上游代码、生产合并与发布仍在本轮范围之外。

## 最值得展开的五个设计

| 设计 | 解决的问题 | 具体机制与依据 | 限制 |
| --- | --- | --- | --- |
| 程序管理推进条件 | 对话里说完成，业务却没有产物 | 查重记录绑定来源；角色与 PRD 版本固定；测试由程序复跑；外部结果读回。见[架构](architecture.md)。 | 程序校验不能证明答案语义一定正确。 |
| 前台安静，后台自动交接 | 多个 Bot 接话、用户反复派单 | 原生提及与来源准入；PRD 就绪自动交小码、小检、小衡；小丘汇总。 | 允许对话不能越过角色和阶段约束。 |
| 识别知识过期 | 换链接后继续使用旧结论 | 观察、可读源码、任务快照、审核版本分开；变化后待复核。见[知识](knowledge.md)。 | 有效引用仍可能不足以支持结论。 |
| 任务可等待、可核对 | 限流或响应丢失造成重复效果 | 持久意图、不确定结果对账、分页与缓存完整性检查。见[流程](workflow.md)。 | 未完成查重仍需新有效判断，不能承诺全部自动恢复。 |
| 未知有明确求助对象 | “我不知道”之后无人处理 | 原来源回答缺口，配置负责人／观察者接收求助，相同阻塞去重。 | 通知送达不等于人工已经接手。 |

## 为什么先三角色，再扩到五角色

早期迭代积累了角色、知识、路由和协作经验；扩大到完整软件团队的设计时，运行接线与维护成本也随之增加。本轮先保留一个 Gateway、一个插件 Worker、一份业务数据库，跑通问答、收单、PRD 与回报，再沿现有状态机加入开发和独立测试。

扩员复用了已运行的来源关联、消息去重、知识版本、PRD、扫描、通知与恢复机制。新增的是分离的开发／测试工作区、必要的原生沙箱和产物阶段。增加两个角色没有变成重建通用调度或权限平台，角色数量也不是系统成熟度的证明。

## 按一个案例展示

1. [Issue #8](https://github.com/90le/steward-feedback/issues/8)：原始需求和后续讨论。
2. [PRD v3](https://github.com/90le/steward-feedback/issues/8#issuecomment-5555649074)：用户目标、范围、验收与修订。
3. [独立评审](https://github.com/90le/steward-feedback/issues/8#issuecomment-5555650888)：对应版本和结论。
4. [五角色交付](https://github.com/90le/steward-feedback/issues/8#issuecomment-5558075155)：作者、测试者、复核者、真实运行 ID。
5. [可操作预览](https://90le.github.io/steward-feedback/prototypes/issue-8/prd-3-03a0a091af3b/index.html)：切换模拟身份，修改未截止投票，再查看通知。

建设过程最直接的体会是：工具或配置存在，只是开始。必须沿真实消息检查上下文、调用、产物和回执，才能区分问题来自模型、检索、权限、协议还是输出处理。设计价值在这些机制在本项目中的组合及实际效果，不宣称行业首创。
