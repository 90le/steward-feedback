PRD v5 · 候选 r1

# 提醒 · 稍后再提醒（snooze）原型 · r1

对应 PRD：`steward-feedback#10` v5（截至 2026-09-07）。这是**演示原型**，用于让评审者与独立测试者从用户视角观察 R1–R15 / AC1–AC19 的可感知行为，不是真实 Octo 功能。

## 启动方式

```bash
# 无依赖，仅使用 Node 24 内置模块
node server.mjs
# 或指定端口
PORT=8080 node server.mjs
```

启动后：

- 打开 `http://127.0.0.1:3000/`，即可进入联调（后端）模式。此时 `<html data-api="1">` 由服务器注入，前端会调用同源 `/api/*`。
- 直接双击 `index.html` 或在纯静态托管下打开，会进入**本地模拟模式**：前端不会 fetch，任何操作只作用于当前浏览器标签页的内存数据（用于查看 UI）。

## 后端接口（仅演示，全部读取内存中的模拟数据）

所有 `/api/*` 请求都需要 `X-Acting-User` 头（`u_alice` / `u_alice2` / `u_bob`）。`u_alice` 与 `u_alice2` 代表**同一个人**的两个入口/端，用来观察 R9/R12 与 AC15/AC16 的跨入口一致性。

| 方法 | 路径 | 作用 |
| ---- | ---- | ---- |
| GET  | `/`  | 返回 `index.html` 并注入 `data-api="1"` |
| GET  | `/api/health` | 健康检查（无需身份） |
| GET  | `/api/reminders` | 列出本人（按 `X-Acting-User` 映射）当前的提醒（含 `state=active/snoozed/done`） |
| POST | `/api/reminders/:id/snooze` | JSON `{snoozeUntil: <毫秒时间戳>}`；服务器校验 `> now`，失败保持原状态 |
| POST | `/api/reminders/:id/cancel` | 取消延后，立即恢复为 active |
| POST | `/api/reminders/:id/done`   | 明确标记已处理，同时取消延后（R9） |
| GET  | `/api/reminders/:id/message` | 返回原消息与所在会话切片，用于真实定位 |

服务器对每个变更接口都做身份与业务校验：他人的提醒返回 403（R6/AC9）；`snoozeUntil <= now` 返回 400 并附带 `now`（AC7/AC13/AC18）；已 done 的提醒不能再 snooze（R15/AC19 一致性）。

## 模拟身份

| 入口 ID | 说明 | 后端映射 |
| ---- | ---- | ---- |
| `u_alice`  | Alice · 入口 A（例如手机） | 本人 = `u_alice` |
| `u_alice2` | Alice · 入口 B（同一个人的网页端） | 本人 = `u_alice` |
| `u_bob`    | Bob · 同群其他成员 | 本人 = `u_bob` |

同一原消息 `m2/m5` 只出现在 Alice 的提醒里，`m1/m4` 出现在 Bob 的提醒里；这样便于观察 R6/AC2/AC12（仅影响本人）。

## 建议的用户视角走查（对应 AC）

1. **AC1 / R1**：以 `u_alice` 打开，对 `r_a_1` 点「稍后再提醒」，选择 `+5s` 或 `+15m` 并确认。该提醒立即从“未处理”移动到“已延后”。
2. **AC3 / R3 / AC14**：等到 `+5s` 到期，点「立即刷新」，该提醒回到活跃列表。点「查看原消息」，右侧原会话真实展示并**高亮**对应消息，且延后/处理状态不变。
3. **AC4 / AC5**：延后中修改时间、取消延后，观察列表实时变化。
4. **AC7 / AC13 / AC18**：在编辑框中把时间改成过去时间（如手动改成 2020 年），点确认——弹出错误提示，**输入保留在编辑框中**，可直接修改后再确认；界面没有出现“已保存”类文字。
5. **AC8 / AC19**：断网或手动改服务端返回失败即可复现；快捷方式：直接对 `u_bob` 的提醒 ID 尝试 POST snooze（前端不给按钮，可用浏览器 DevTools）——后端返回 403，界面 toast 报错，原状态保留。
6. **AC9 / R6 / AC2 / AC12**：切换到 `u_bob`，只能看到 Bob 的两条；Alice 的操作不影响 Bob。
7. **AC10 / AC11**：Alice 先对 `r_a_2` 延后到 `+5s`，然后立刻点「标记为已处理」；到达 `+5s` 并刷新，该提醒不再出现（AC10）。若不点已处理，只点「查看原消息」，到点仍会重现（AC11）。
8. **AC15 / AC16**：Alice 在入口 A（`u_alice`）标记已处理，切换到入口 B（`u_alice2`）后点「立即刷新」或等待轮询，看到同一提醒已为已处理，不再重现。
9. **AC17 / R13**：打开某条提醒的编辑框，输入 `+15m` 后**静置 6 秒以上（页面每 3 秒自动刷新一次）**，输入框内容保持不变；此时确认，保存的就是刚才看到的那个值。

## 与真实功能的边界

- **只是原型**：所有数据在进程内存中，服务重启即清空。没有真实群消息、没有真实通知、没有推送。
- **身份是模拟的**：`X-Acting-User` 头是不带鉴权的入口标识，仅用于演示同一人多入口一致性；不接任何真实用户系统。
- **不改上游**：不会修改任何 octo-server 源码或调用其真实 API；仅在本地 HTTP 服务上演示。
- **PRD 未固化的开放问题（OQ1–OQ12）** 在原型里都用了保守的默认展示（例如快捷项 `+5s/+15m/+1h`、任意 datetime 输入），仅作为可观察演示，不代表已被决定。
- **沙箱预览包装限制**：真实预览环境中，表单不能靠原生 submit 事件路径；本原型全部使用 `type="button"` + click 处理，未使用原生表单提交、页面跳转、localStorage、iframe 或跨域资源。
